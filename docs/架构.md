## 为什么短剧要单独一个进程

- 短剧的接口需要**请求签名**（x-gorgon 一族），视频以加密分发格式提供，需由该内核在本机完成格式转换后才能播放。
  这套逻辑由 [hongguo-web](https://github.com/sunnysky123/hongguo-web) 实现，纯 Node、零依赖。
- 我们的 Next.js 应用不重复实现它，只做「同源转发 + 自己的 UI」，这样升级内核时只替换它的 `server/src`，页面逻辑不受影响。

## 为什么用 rewrite 而不是 iframe / 开端口

| 方案 | 问题 |
| --- | --- |
| iframe 嵌 `:8000` | 两个地址要记、局域网设备要额外放行端口、跨域 |
| 直接调 `http://127.0.0.1:8000` | 浏览器 CORS、HTTPS 下混内容 |
| **Next rewrite `/hg-api/*`** | 浏览器只认 8080，同源、无 CORS、局域网天然可用 ✅ |

## 数据与状态

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 访问密码 / 默认源 | `app/.env` | 安装版在 `%LOCALAPPDATA%\Programs\MFlixTV\app\.env` |
| 观看历史（短剧） | 浏览器 `localStorage` + 服务端 `.data/history.json` | 两端按「较新优先 + 集级取最大」合并 |
| 播放器偏好（倍速/音量） | `localStorage` `hg_player_prefs` | 跨集、跨次保留 |
| 影视播放进度 | IndexedDB（MFlixTV 原有） | 按 `源:影片:集` 存 |
| 短剧转换缓存 | `hongguo/server/stream-cache/` | 上限 120 个，按修改时间淘汰 |

## 进度续播的两套规则

| 场景 | 位置 | 规则 |
| --- | --- | --- |
| 选集切集 | `/hongguo` | 读该集历史，回退 3 秒 |
| 同名剧换源 | `/hongguo` | 同集号，进度 **−10 秒** |
| 主站换源 | `/watch` | 通过 URL `position` 传参，进度 **−10 秒** |

统一原则：**只往前，不往后**。不同源码率、片头长度不同，往后挪必然跳过剧情。

## 更新链路

```
托盘「检查更新」 → tools/update.ps1 -Part all
  ├─ kernel: 拉 hongguo-web（4 镜像）→ 备份 → 替换 → 重打 content_type 补丁 → 重启 8000
  └─ sources: 内置池 + 现配置 + 远程列表 → 并发探活 → 快源白名单排序 → 取 6 个写回 .env
               → 配置有变化才重启 8080
```
