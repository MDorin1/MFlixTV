# 按键与焦点规范（电视 / 桌面）

写给两套 UI 的同一份键位表：**安卓电视端**是 `android/app/src/main/assets/tv.html`（单文件，自带几何导航与按钮条），**PC / macOS 端**是 `app/` 的 Next.js（`lib/remote-nav.ts` 几何导航 + `lib/remote-engine.ts` 遥控指令 + `components/player-shell.tsx` 播放器快捷键）。

两套实现永远不可能合成一份代码（一个是原生 WebView 里的单文件，一个是 React），但**同一个键只能有一种结果**。这份文档就是那个"唯一结果"：改动任何一个平台前，先看这里写的期望行为，改完把「现状」一列更新。

---

## 一、三条硬规则

1. **一个键只归一套逻辑。** 播放器在场时，方向键归播放器；播放器不在场时归焦点导航。任何"先试 A、失败再试 B"的写法都会让同一颗键时快时慢——播放器按钮即使在控制条收起时也满足"可见"，这就是 1.10 里 ←/→ 有时跳进度、有时挪焦点的根因。
2. **首屏必须有焦点。** 页面渲染完成后 200ms 内至少有一格带焦点环；没有焦点时按确定键必须等同于按了个空键，属于缺陷。
3. **焦点不能丢。** 打开浮层、换集、换源、返回一层之后，焦点要么回到进入前那一格，要么落在新容器的第一格，不允许变成"哪都没有"。

## 二、键位表

### 2.1 浏览态（首页 / 搜索 / 详情 / 直播列表）

| 键 | 动作 | 焦点移动 | 提示文案 |
| --- | --- | --- | --- |
| ↑ ↓ ← → | 几何导航到该方向最近的一格 | 是 | 无 |
| 确定 | 激活焦点所在元素（进入 / 播放 / 展开） | 视目标而定 | 无 |
| 返回 | 逐层退：浮层 → 页面 → 首页 | 回到上一层的原焦点 | 无 |
| 菜单键 / 长按确定（Shield 无菜单键） | 展开当前行的「更多」或呼出面板 | 是 | 按上下文 |
| 数字键（搜索页） | 输入 | 否 | 无 |

### 2.2 播放器态（点播）

| 键 | 动作 | 焦点移动 | 提示文案 |
| --- | --- | --- | --- |
| ← / → | 快退 / 快进 **10 秒** | **否** | `快退 10s` / `快进 10s` |
| ↑ / ↓ | 短按 ↑ 只亮**顶部信息**（片名 · 集数 · 线路），3 秒自动收起；短按 ↓ 亮**整条控制条**；**长按切上一集 / 下一集** | 否 | 顶部信息条（首次另给「长按 ↑ / ↓ 切上一集 / 下一集」） |
| 确定 | 播放 / 暂停（TV 暂停后方向键自动进按钮条） | 否 | 无 |
| 菜单键 / 长按确定 | 进按钮条 | 是（落到「播放」） | `方向键选择 · 回车执行 · 返回退出` |
| 按钮条内 ← / → | 在按钮之间移焦点；**停在进度条上时才是快退/快进** | 是 | 无 |
| 按钮条内 ↑ / ↓ | 在按钮之间移焦点 | 是 | 无 |
| 按钮条内确定 | 执行该按钮 | 否 | 无 |
| 返回（**焦点在按钮条内**） | 只收按钮条，回播放器，仍在播放 | 是（回播放器） | 无 |
| 返回（**焦点不在按钮条内**） | **一次退出播放**，回详情页，焦点落回刚看的那一集。**不设「第一次收条」** | 否 | 无 |
| Alt + ← / → | 上一集 / 下一集（PC 键盘） | 否 | 无 |

**为什么要标「焦点移动」一列**：电视用户不看说明，靠肌肉记忆。同一个键有时挪焦点有时不挪，用户就会觉得遥控器坏了。

### 2.3 提示文案（两边必须一字不差）

| 场景 | 文案 |
| --- | --- |
| 快退 / 快进 | `快退 10s` / `快进 10s` |
| 音量 | `音量 N%` |
| 进按钮条 | `方向键选择 · 回车执行 · 返回退出` |
| 换线路 | `已换到「线路名」` |
| 首屏无头图（兜底焦点） | 无（静默落到第一格） |

## 二·五、双端实现约定（1.19 起）

这套东西有两份实现：**电脑端**（Next.js，`app/src/lib/*`）和**安卓端**（Kotlin，`android/app/src/main/java/com/mflixtv/app/*`，电视界面跑的也是它）。两边各自实现一套规则，改动只落一边，用户就会看到两套数字。

**硬规则：凡属于下面四类，两边都要落，落一边算没做。**

1. **判定逻辑** —— 什么算完结、什么算「最新一集」、什么算归档源、日期从哪个字段取
2. **显示文案** —— `2016起`、`最新一集 2025-10-20 · 源 12 个月前更新`、`上架时间 …`、`全34集 / 更新至N集`
3. **排序规则** —— 按 `recencyYear` 排，不是按 `vod_year`；同日期的再看最新一期。**搜索结果**是三段：标题完全相同置顶（其余一律平等，两档不细分前缀/包含）→ `recencyYear` 降序 → 原始标题，见下图「搜索排序」那一行
4. **阈值常量** —— 归档 90 天、琥珀色门槛 30 天

**对照表（同一条规则的两个落点）**

| 规则 | 电脑端 | 安卓端 |
| --- | --- | --- |
| 备注归一（全N集/更新至N集/更新至日期/已完结） | `app/src/lib/remarks.ts` `formatRemarks()` | `Freshness.kt` `formatRemarks()` |
| 从备注取最新一期日期 | `remarks.ts` `latestEpisodeDate()` | `Freshness.kt` `latestEpisodeDate()` |
| 排序年份（跨年节目以最新一期为准） | `remarks.ts` `recencyYear()` | `Freshness.kt` `recencyYear()` |
| **搜索排序**（标题精确度 → 年份 → 片名） | `search-sort.ts` `titleRank()` / `sortSearchResults()`（`/api/search` 调） | `Freshness.kt` `titleRank()` / `Sources.search()` |
| 一条源的最新内容日期 + `dateSource` | `source-freshness.ts` `latestInRaw()` | `Freshness.kt` `latestInRaw()` |
| 归档判定（**只认 remarks**） | `source-freshness.ts` `isArchivedSource()` | `Freshness.kt` `isArchived()` |
| 体检那格文案 | `source-freshness.ts` `freshnessLabel()` | `Freshness.kt` `freshnessLabel()` |
| 卡片年份 / 详情页那行 | `video-card.tsx` / 详情页 | `tv.html` `paintMeta()` / `paintHero()` |

改完两件事都要做：电脑端 `npm run test`（`remarks.test.ts` 有断言），安卓端 `gradle -p android assembleRelease` 能编过、电视界面用 `D:\Build\_tvtest\` 那套 mock 看一眼实际渲染。

**历史教训**：1.12 的「2016起 + 按最新一期排序」和 1.15 的「dateSource + 归档闸」只落在 Next.js，安卓端（含电视）一个月里一条都没有——用户在电视上看到的还是老排序。

## 三、当前实现对照

| 规则 | 安卓电视（tv.html） | PC / macOS（Next.js） | 状态 |
| --- | --- | --- | --- |
| 首屏焦点 | `paintFocus($('heroPlay'))` 首页挂载即钉 | `seedFocus()`（1.11 起）：固定时间点 + `MutationObserver`，钉 `[data-rc-first]` | ✅ 一致 |
| 播放器 ← / → | `seekByDirection(-1/1)`，不进按钮条 | `player-shell.tsx` ±10 秒，`remote-engine` 在播放器内不再走 `nav.move` | ✅ 一致 |
| 播放中 ↑ / ↓ | 1.19 起：短按 ↑ 只亮顶部信息 3 秒、短按 ↓ 亮整条控制条、长按切集（`topInfo()`、`handlePlayer`） | 控制条收起时 = 音量 | ✅ 一致（都是「上=信息 / 下=控制条」的思路，PC 侧用控制条承载） |
| 返回（播放页） | 条内收条 / 条外一次退出 `handlePlayer('back')` | 分层退 | ✅ 一致（见 2.2） |
| 进按钮条 | 暂停自动进 / 菜单键 / 长按确定 | 控制条亮起时 `nav.move` 进入 | ⚠️ 偏差 |
| 按钮条内 ← / → | 停在进度条上才是 seek | 同上（`arrowRoute()` 永远给 seek，条内不给焦点移动） | ⚠️ 偏差 |
| 返回逐层退 | `handle('back')` 分层 | `layeredBack()` + `nav.clear()` | ✅ 一致 |

### 待收口的偏差（不阻塞，按顺序做）

1. **进按钮条入口**：电视端有「暂停自动进条」这条老人友好的路子，PC 端没有。下一步在 PC 端补：暂停时若遥控焦点为空，自动把焦点交给控制条第一颗按钮。
2. **条内 ← / →**：两边都要「停在进度条上才是 seek」，其余情况移焦点。PC 端目前 `arrowRoute()` 一律给 seek，需要在 `nav.current()` 是进度条元素时才放行。
