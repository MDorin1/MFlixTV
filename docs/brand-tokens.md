# 双产品视觉规范：一致的 token，各自的色相

用户的要求原话：「MFLIXTV 和 MFLIXMUSIC 风格要一致，但要保持各自的特色；MFLIXTV 红黑配色，MFLIXMUSIC 绿黑配色；MFLIXMUSIC 多参考 Apple Music 的界面、交互、图标。」

拆成一句话：**统一的是数值（形状、节奏、字体、图标），不统一的是色相和版式。**

这条必须先定死，否则两个 Bot 各按理解做，做出来还是两套。

## 二、必须一致（数值层，两边抄同一套）

### 2.0 谁说了算

**已落地的实现优先于这份文档。** 两处按代码改文档，不改代码：

- `--accent:#3ecf8e` / `--accent-2:#34d399`：初版把两个值写反了，音乐端已经按 `#3ecf8e` 当主色铺开（44 处 `var(--r-*)` 配套的那套），为了文档去改 44 处没有收益，改文档。
- 图标线宽 1.8px（见 2.5）：不是 2px。

改文档的另一种情况是本文档写错了口径。除此之外，**两边实现不一致时，先问哪边对，再统一，不要各改一半。**

### 2.1 动效

```
--ease: cubic-bezier(0.22, 1, 0.36, 1);   /* 进出场、卡片展开、页面切换 */
--ease-in-out: cubic-bezier(0.4, 0, 0.2, 1); /* 位置移动、淡入淡出 */
--dur-fast: 120ms;   /* 焦点环、按钮按下 */
--dur-base: 200ms;   /* 常规过渡 */
--dur-slow: 320ms;   /* 页面/全屏播放器展开 */
```

两边都改成这一套。影视端现在是 `.22,.61,.36,1`，与音乐的 `0.22, 1, 0.36, 1` 手感不同——这是"看着不一致"最直接的来源之一。

### 2.2 圆角（四档，禁止再写散值）

```
--r-sm: 8px;     /* 标签、chip、小按钮 */
--r-md: 12px;    /* 卡片、输入框、列表行 */
--r-lg: 16px;    /* 大面板、全屏播放器容器 */
--r-full: 999px; /* 只给胶囊按钮 */
```

**单位一律用 px**（影视端现有 `.35rem`/`.4rem`/`.5rem` 与 px 混用，先统一再变量化）。

**正圆保留 `50%`**：头像、状态圆点（音乐端 11 处，含 `.np-src-dot`）必须用 `50%`，并进 `--r-full` 会被做成圆角方块。

音乐现在 `--radius:14px` 定义了却没被用起来，`7/9/10/12/22px` 散着写——先收敛到四档，再谈"一致"。

### 2.3 字体

```
font-family: "HarmonyOS Sans SC", "MiSans", "PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif;
```

以影视端为准（它已经写着）。音乐端现在没声明，接同一行。

### 2.4 间距

4 的倍数：`4 / 8 / 12 / 16 / 24 / 32 / 48`。不再出现 `13px`、`18px`、`26px` 这类。

### 2.5 图标

同一套线性图标，规则固定：

- 24×24 网格，线宽 **1.8px**，圆角端点与圆角连接（`stroke-linecap:round; stroke-linejoin:round`）
  - 为什么不是 2px：音乐端图标实际渲染尺寸是 19px（`.icon-btn svg`）与 21px（`.np-fctrl .icon-btn svg`），2px 描边在 19px 上会明显变粗、看着沉；而两边现有分布已经趋同（音乐 1.8×14 / 1.7×13，影视 1.9×14 / 1.8×9），1.8 是两边迁移量最小的共同值。影视 1.9→1.8 在 3 米外看不出区别。
- 只用 `currentColor` 描边，不填色（画面小圆点除外）
- 同一语义只能有一个图标：播放是实心三角、暂停是双竖条、下一首是三角+竖条，不许两边各画一个

### 2.6 焦点环（电视端）

```
outline: 2px solid var(--accent);
box-shadow: 0 0 0 4px color-mix(in srgb, var(--accent) 26%, transparent);
```

形状、宽度、外发光半径一致，**颜色各自用主色**。这样电视上换到哪个 App，焦点环的"手感"一样、颜色不一样。

## 三、必须不同（各自的特色，不许互相抄）

| | MFlixTV | MFlixMusic |
| --- | --- | --- |
| 色相 | 红黑：`--accent:#e50914` / `--accent-2:#ff4d57` | 绿黑：`--accent:#3ecf8e` / `--accent-2:#34d399` |
| 背景 | 纯黑 `#000`（影院感） | 近黑带蓝 `#08080b`（长时间听歌不刺眼） |
| 主版式 | 横排海报墙，海报 2:3，一行一张卡（6–8 张） | Apple Music 式：大封面 + 列表行 + 常驻迷你条 |
| 内容密度 | 高密度，首屏要塞 4–5 排 | 低密度，行高更大，留白更多 |
| 身份象征 | 片名大字 + 红色进度条 | 专辑封面取色做背景渐变 |

**不许做**：把音乐改成横排海报墙、把影视改成列表行。那叫"一致"，但把各自的产品逻辑抹掉了。

---

## 四、MFlixMusic 参考 Apple Music 的具体四件事

不说"参考一下"，说清学哪四条：

1. **常驻迷你播放条**：底部一条（高 68–72px），左小封面 + 标题/歌手两行 + 播放/下一首；点条上滑展开全屏播放器，下滑收回。全屏展开用 **封面位置连续过渡**（起点是条上的缩略图、终点是大封面），不是淡入。
2. **列表行形状**：左 48×48 圆角封面（`--r-sm`）+ 主标题 1 行 + 副标题 1 行（灰）+ 右侧 `⋯`；行高 64px，分隔线只在左侧缩进处出现（不从屏幕左边缘通到底）。
3. **背景取色**：全屏播放器与详情页用当前封面主色做一层低透明度径向渐变铺底，上方加 `backdrop-filter: blur(40px)`；没有封面时退回纯背景色，不报错。
4. **控件层级**：播放页从上到下 = 大封面 → 标题/歌手 → 细进度条（4px，拖动手柄 12px）→ 主控行（上一首 44px / 播放 64px / 下一首 44px）→ 次控行（随机、循环、音量、更多，32px 线性图标）。

图标全部按 2.5 的规则重画或统一线宽，不许混用艺术字图标和 emoji。

## 五、改动清单（分派）

### MFlixMusic（音乐软件）

1. 主色换绿：`--accent:#3ecf8e`、`--accent-2:#34d399`，把 `var(--red)` 那 **15 处**（`style.css` 12、`artist.css` 1、**`app.js` 2**）全部改成 `var(--accent)`；同时把硬编码的 `#3ecf8e`（12 处）与 `#34d399`（3 处）收进变量；`--red`/`--red2` 从 `style.css` 删掉（`remote.html` 只删定义，它没有引用）
   - **`app.js` 那 2 处不能漏**：定义一删，js 里的 `var(--red)` 取不到值，那两块颜色会掉成继承色
2. `--ease` 换成 `cubic-bezier(0.22, 1, 0.36, 1)`，补 `--dur-fast/base/slow`
3. 圆角收敛：`--r-sm/md/lg/full` 四档替换 `7/9/10/12/22px` 散值
4. 字体按 2.3 声明
5. 按第四节四条做 Apple Music 式改造，**先做 1–4（半小时的事），再做 5**

### MFlixTV（影视开发）

1. `--ease` 换成同一值，补三个 `--dur`
2. 圆角变量化到四档
3. 主色变量名对齐成 `--accent`/`--accent-2`（值不变，仍红黑），这样两边 CSS 长得一样、只有变量值不同
4. 图标按 2.5 统一线宽（`tv.html` 里现有内联 SVG 逐个看一眼）

### 两边都不做

- 不统一背景色值（黑得不一样是对的：影院要纯黑，听歌要柔和）
- 不统一版式（横排海报墙 vs 列表行）
- 不为"看着一样"改字重、字号阶梯里已经调好的组合

## 六、验收（可命令行核，不靠肉眼）

```powershell
# 1) 动效曲线两边同一个值
Select-String -Path "D:\...\tv.html","...\style.css" -Pattern "--ease\s*:"

# 2) 音乐端红色归零（含 js）
Select-String -Path "...\public\*.css","...\public\*.html","...\public\*.js" -Pattern "var\(--red\)|#e50914"

# 3) 圆角散值收敛（非 8/12/16/999/50% 的 border-radius 应为 0；50% 为正圆，保留）
Select-String -Path "...\public\style.css" -Pattern "border-radius:\s*[0-9]+px"

# 4) 字体栈两边都含 HarmonyOS Sans SC
Select-String -Path "...\tv.html","...\style.css" -Pattern "HarmonyOS Sans SC"
```

肉眼最后看一次：同一张 1080p 截图里，两个 App 的**圆角、线宽、动效节奏**要能认出是一个团队做的；**颜色和版式**要一眼分清是哪个产品。

## 八、本轮判据修正（2026-11-09，审核员实测后）

第 1–7 条是按实测数字改的，前面正文已同步，这里记一笔为什么改：

| 原写法 | 改成 | 依据 |
| --- | --- | --- |
| `var(--red)` 15 处都在三份 CSS | `style.css` 12 + `artist.css` 1 + **`app.js` 2** | 只改 CSS 会让 js 里两处失效声明，颜色掉成继承色 |
| 绿体系「可直接复用」21 处 | 大部分是硬编码（`#3ecf8e` 12、`#34d399` 3），`var(--green)` 只 2 处 | 换主色要先收散值，不然只是换了变量名 |
| 音乐「未声明字体」 | 有 5 处 `font-family`，都不含 `HarmonyOS Sans SC` | 措辞不准会让验收句写错 |
| 图标线宽 2px | **1.8px** | 音乐图标实际 19/21px，2px 太沉；两边分布已趋同 1.8 |
| 圆角四档含 `--r-full` 收所有大圆角 | 正圆保留 `50%`，`--r-full` 只给胶囊按钮 | 音乐 11 处 `50%` 是头像与小圆点，并进去会变圆角方块 |
| 圆角四档直接替换 | 先把 `.35rem`/`.4rem`/`.5rem` 统一成 px 再变量化 | 影视端单位混用 |

**规模**：音乐四份 CSS 共 98 处 `border-radius`（`style.css` 54 / `tv.css` 26 / `phone.css` 13 / `artist.css` 5）；影视 `tv.html` 88 处。这不是半小时的活，按文件分批提交，每次报「本文件散值 N → 0」。
