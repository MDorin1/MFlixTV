## 一、项目原点

2026-10-25 开工。起点是 [LibreSpark/LibreTV](https://github.com/LibreSpark/LibreTV) 2.21.0 —— 一个纯网页形态的影视聚合播放器：输入点播源接口（苹果CMS 协议）→ 搜索 → 取 m3u8 → 播。

原始的形态有三个绕不过去的限制，整个项目的第一阶段都在解决它们：

1. **只能在浏览器里跑**，关掉标签页就没了，也没有本机服务；
2. **一个源挂了就全废**，没有任何测速、排序、补源；
3. **没有「谁在看」的概念**，局域网里别的设备想看得自己再配一遍。

于是定了三件事，一直贯穿到现在：

- 把 Next.js 应用 + Node 运行时 + ffmpeg **打进安装包**，装完就是一台本机影视服务器（默认 `8080`）；
- 局域网里任何设备用浏览器打开 `电脑IP:8080` 就能看，**服务端在电脑上，对面不装任何东西**；
- 所有画面、取流动作都在服务端做，客户端只负责显示。

后来「服务端」这个概念一路长下去，长成了今天的三个端：

```
电脑（Windows 安装版）  →  Next.js 15 + Node 22，端口 8080
安卓 / 电视（同一个 APK）→  Kotlin + 内置 Node 20，端口 8080
任何浏览器（手机/平板/别人的电脑）→ 直接访问上面任意一台的 8080
```

## 三、阶段 A：桌面版从 0 到 1.0（10-25）

### 做了什么

- 把 Next.js 产物 + Node 22 运行时 + ffmpeg 一起冻进 `packaging/stage`，用 Inno Setup 6 打成单个 exe；
- 托盘常驻（启停服务、复制局域网地址、打开浏览器），关窗口不关服务；
- `tools/update.ps1`：候选源 → 并发探活 → 按**实测拉流速度**排序 → 只留 6 个快源写回 `.env`；
- 短剧专区 `/hongguo`：单独一个 Node 进程（`hongguo-web`，端口 8000），主站用 Next rewrite `/hg-api/*` 转发，浏览器只认 8080。

### 撞上的问题

| 症状 | 根因 | 解法 |
| --- | --- | --- |
| 装完打开是空白页 / 500 | 安装包里没有 `.next` 或路径解析错 | `packaging/build-portable.ps1` 加硬闸：缺 `.next`、缺 `DEFAULT_SOURCES`、缺 `PASSWORD` 直接中止构建 |
| 装完提示「必须设置 PASSWORD」、源列表空的 | `.env` 是运行时生成的，安装包没带 | 把默认 `.env` 打进包，首次启动只做合并不覆盖 |
| 覆盖安装报「尝试替换已存在的文件时出错」 | 上一版进程还占着文件 | 安装前先结束本目录的 node 进程（只杀本目录，不误伤别的 node） |
| 装到 D 盘后 404 | 启动器把相对路径当成了安装目录 | 启动器按 exe 自身位置算根目录，并打日志 + 探活 8080 |
| 补源之后反而变卡 | 判据用的是**搜索延迟**，把拉流只有 18 KB/s 的站也选进来了 | 换成拉流速度白名单 + 只留 6 个源；取消每天自动跑（会自动重启服务打断播放） |

### 留下的决定

- **源列表必须随包内置**。用户换机器、发给别人，都不能出现空源。
- **安装目录可任意盘**。这条后来在安卓那边以另一种形式又犯了一次（见阶段 D 的端口/路径问题）。
- 合规口径从这一阶段就定了：界面只写「自建影视资源聚合播放器」，不出现第三方商标指代；`LICENSES/` + `NOTICE.md` 随包附带。

## 四、阶段 B：Netflix 化（10-26）

### 做了什么

- 全站字体、间距、圆角、焦点态重做（`-apple-system` / PingFang / HarmonyOS Sans）；
- 采集源资料页 `/detail/<源>/<片>`：海报、年份、地区、类型、简介、导演主演、播放源、剧集一页看完；
- 演员检索（豆瓣联想 + 演职员表模糊匹配）、相似影片、TOP 10、继续观看、我的清单；
- **处处可点**：演员名、片名、豆瓣条目、换源面板里的「看资料」、历史记录，凡出现名字的地方都能点进资料页。

### 撞上的问题

**导航上翻过一次车。** 试过左侧竖排导航（Netflix 桌面版那样），上线后观感偏重、条目太多，用户直接否掉，回退到顶部导航并压缩入口数量。教训写进记忆：入口要少而精，别拿导航当功能列表用。

**海报片名读不出来。** 白底或浅色封面上，白色片名等于隐形。解法是海报底部压一层深色渐变遮罩，片名压在遮罩上——不是简单加描边（描边在复杂封面上更乱）。

**豆瓣封面 418。** 图床按 Referer 拒外链，改走本机 `/api/proxy` 转发并带正常 UA / Referer，转发失败再退回直连。

**海报墙每次进都重排、白屏一下。** 改成 stale-while-revalidate：本地缓存先画、后台再请求覆盖。点播首页与短剧专区必须同一套，否则两个页面的观感不一致。

### 留下的决定

- 任何列表页都先读缓存立即渲染，再后台刷新。
- 搜索结果一律按发行时间倒序，最新的一季在最前。
- 资料页必须把同名的所有季列全（缺一季用户就以为没有）。

## 五、阶段 C：短剧内核与预取（10-26，最痛的一段）

短剧和点播不是一个东西：它的接口要请求签名，视频是加密分发的，得在本机完成格式转换才能播。所以有独立内核进程，主站只做同源转发。**这段是整个项目里返工最多的地方，值得细看。**

### 第一版：串行预热，直接被否

点第 1 集时串行预热第 2–5 集。问题：**预取和正在播的那一集抢带宽**。实测出现过点一集等 40 多秒——预热把当前集的请求挤到超时。

### 第二版：去掉浏览器侧抢流式预取

只保留内核预热。仍然不够快，但至少不拖累当前集。

### 第三版：等「真的开始播」之后再预热

把预热触发点从「进详情页 / 点集」挪到「当前集 `currentTime > 0` 之后」，并错开 2 秒、只热 3 集。这一版才真正解决「预热变慢」的悖论。

### 第四版：HLS 分片 + 内核预热队列（1.3.1）

- 内核新增 `/hls`：把已解密的整集 MP4 用 ffmpeg `-c copy` 切成 2 秒 fMP4 分片，**分片就绪即播**，不等整集；
- 播放器改用 hls.js 播 `/hls`；不支持 MSE 或分片通道报错时自动退回 `/stream` 整集直链；
- `warm.js` 后台队列：2 路并发、同集去重、支持插队（下一集带 `priority=1`）、窗口 4 集；
- `/prewarm` 返回 `{ vid, status, queue }`，能直接看出是在排队还是在下载。

### 第五版：窗口 6 集、并发 3、插队优先（1.3.2）

用户的实际用法是**跳着点**（正看第 53 集，直接点第 56 集），所以「只备下一集」不够：窗口扩到 6 集，用户点选的那一集插队到队头。

还有一个隐蔽 bug：**换集时把整条预热调度给中止了**，导致第二次换集之后队列永远是空的。改成「换集只调整队列，不中止调度」。

### 这一段的红线

后来定的取流红线就是从这儿来的：`hls` 配置、预取器、分片缓存、`/api/proxy` **一行不许改**。任何优化必须能证明「起播速度持平或更好」，否则不做。

> 补充：11-01 的用户表态是「短剧继续走整集下载解密路线，但并发化提速：Range 多连接并行 + 多线程并行解密 + 结果落盘缓存」。这条还没做，记在[遗留](#十一遗留与下一步)。

## 六、阶段 D：安卓独立 App（10-28 → 10-30）

### 路线是怎么定的

一开始想的是「WebView 遥控壳连电脑」，用户否掉。要的是**独立 App**：APK 内置整套 Node 服务（主站 8080 + 短剧内核），手机开着时同一局域网的设备访问 `手机IP:8080` 就能用。

技术前提卡在 Node 版本上：官方 `nodejs-mobile` 最新内嵌 Node 12.19.0，跑不了需要 Node ≥ 18.18 的 Next 15。结论是**用 NDK 交叉编译 Node 20（arm64）**自己带。

### 从 0.2 到 0.35 的连环坑

这是全项目密度最高的一段，几乎每一个版本都是一个具体故障。

| 版本 | 症状 | 根因 | 解法 |
| --- | --- | --- | --- |
| 0.2 | —— | —— | 安卓端重做：首页片单 + 详情 + 内置 hls.js 播放器；m3u8 里的分片、子播放列表、AES 密钥、init 段全部改写成 `/api/proxy?url=`；206 透传（此前一律回 200，拖进度等于重下整个文件） |
| 0.3 | 一打开就闪退 | `AppCompatActivity` 没配 AppCompat 主题 | 加 `Theme.MFlixTV`；前台服务改成**先亮通知再起服务**（Android 8+ 要求 5 秒内 `startForeground`） |
| 0.6 | 一直卡在「正在载入片单」 | 采集站证书缺中间证书，Android 的 Java HTTPS 校验比桌面严；https 打不通没退路 | 所有对外请求统一走 `Net`：证书宽容 + https 失败退 http + 逐个源自检 + 全失败不覆盖旧缓存 + 失败页给四条活路 |

| 0.23 | 老盒子白屏 | 按 API 34 编译、在 API 25 上跑，用了 API 26 才有的 `WebView.getWebChromeClient()` | 加系统版本守卫 + try/catch |

| 0.26 | 「播放好卡」 | **不是硬件**，是 WebView 在软解（同一路流交给系统硬解播放器 CPU 0~1%） | 新增外部播放器（MX / VLC / 盒子自带），把地址交给系统播；走整条线路的 m3u8 播放列表而不是单集直链（直链会被源站拦） |
| 0.31 | 首屏切掉半张卡 | 大图区高度按经验值写的 | 按实测收高（1080p −48px / 720p −36px，换分辨率自动重算）；返回首页还原滚动位置与焦点卡 |
| 0.32 | 源陆续挂掉，用户得自己找源 | 没有测速与维护 | 按延迟排序取源、连续失败沉底、30 分钟体检、一个源都不通时自动从远端清单拉源合并重测 |
| 0.33 | 播放失败只能返回 | —— | 自动换线路（电视端 + 手机端） |
| 0.35 | 换集后进度记错 | 看的是上一集的记录 | 播放记录按设备独立、短剧走纯本机 localStorage、换集进度以新一集为准 |

### 这一阶段最值钱的三条经验

1. **「电脑能用、手机不行」先怀疑证书链和 WebView 版本**，不要怀疑业务逻辑。
2. **布局 bug 先量 `innerWidth` / `clientWidth` / `scrollWidth` 三个数**。0.21 那个「按钮被裁」如果只看截图，会以为是 `overflow` 或者 `flex` 的问题，量了三个数十秒就定位。
3. **老设备要拿真机量，不要靠推测**。0.22 的「糊」看起来像 CSS 参数没调对，实际是源里没有那张图。

## 七、阶段 E：电视端与遥控器（10-29 → 10-31）

### 电视端 10 英尺界面（0.18）

同一个 APK，装到电视上自动认出来（Leanback / `UI_MODE_TYPE_TELEVISION` / 无触摸屏任一命中），进 `tv.html`；手机装的还是手机界面，播放路径完全不动。也可以 `adb shell am start -n com.mflixtv.app/.MainActivity --ez tv true` 强制。

电视端要单独解决的事：

- **焦点导航**：方向键的几何导航要「正下方优先、横排不串排、一排最左不甩屏、滚动容器能到底」，这套算法迭代了三轮才稳；
- **遥控器按键**：Shield TV 2017 的遥控器**没有 MENU 键**，所以播放页按钮条靠**长按确定键**（原生 `dispatchKeyEvent` 计 `repeatCount`）呼出，菜单键只作备用；
- **焦点环**：从红色辉光改成纯白描边 + 放大 1.13，同排其余海报压暗；
- **老内核兜底**：`aspect-ratio`、flex `gap()`、`env(safe-area-inset-*)`、CSS Grid、`inset` 在旧 WebView 上都不认，全部加了降级；再加一道能力闸（缺 `fetch`/`Promise`/`WeakMap`/`JSON`/`Object.assign` 直接提示「WebView 太旧」而不是白屏）。

### 手机扫码变遥控器（1.2.0 → 1.2.6）

设计要点（也是踩出来的）：

- **会话级而不是设备级**：每个打开页面的标签页各领一个 6 位 token，二维码里带这个 token，扫它的设备只控制那一个页面，互不串台；
- **长轮询而不是定时轮询**：被控端 `GET /api/rs/host?wait=700`，手机一按到被控页真的动，实测 **9ms**；
- **状态回传**：音量、倍速、播放进度、选集、线路都从被控页回传，手机上能看见自己按到了哪；
- **长按连发**：420ms 后每 140ms 一步，音量与倍速发绝对值不发漂移量；
- **方向键是几何导航**：在目标半平面里找最近且最正对的可点元素，盲点在于视口外要给软惩罚、容器边界要挡住；
- **全屏必须真假分开**：`requestFullscreen` 和画中画都要求真实用户手势，遥控指令触发必然被浏览器拒绝。所以安卓/电视走原生桥改窗口状态（真整屏），桌面版用全屏应用窗口打开，遥控按全屏时「先铺满、等下一次真实点击/按键补成整屏」。

这一路的问题与修法：

| 症状 | 根因 | 解法 |
| --- | --- | --- |
| 遥控方向键和确定键全失灵、红框不出 | 服务端路由表漏了 `/rc-nav.js`（404），`MFlixRCNav` 是 undefined | 补路由 + 页面脚本自拉取兜底 |

## 八、阶段 F：版本收口与发布体系（10-31）

### 版本规则（用户定，之后都照这个走）

- 桌面与安卓**同号**。以前桌面走 1.2.x、安卓走 0.x / 1.x，同一个版本号两边对不上；
- **一个版本一条 Release，里面同时放 Windows 安装包和安卓 APK**。安卓不单独开 Release；
- Release 只保留当前版与历史归档（现在 v1.0 / v1.1 / v1.2 三条）；
- Release 说明一律中文；公开文字里不留具体影片名、演员名，截图里的片名与海报打码；
- 同一个版本号内替换资产，不为了「发过一次」就往上堆版本号。

### 发布链路（可照抄）

```
桌面：packaging\build-portable.ps1 -Out <repo>\packaging\stage -NodeExe <node> -FfmpegBin <ffmpeg> -HongguoDir <kernel>
      → csc.exe /target:winexe /win32icon:app.ico Launcher.cs
      → ISCC.exe MFlixTV.iss            （约 168 秒）
      → D:\Build\dist\MFlixTV-Setup-<版本>.exe

安卓：$env:JAVA_HOME='C:\Java\jdk17'
      gradle assembleRelease --no-daemon -q
      → android\app\build\outputs\apk\release\app-release.apk
      → adb install -r → dumpsys package com.mflixtv.app 核对 versionCode/versionName

发布：更新 notes-<版本>.md → scripts 里 patch Release 说明 + 上/替换资产 → 核对线上字节数与本地一致
```

**踩过的发布坑**：

- 安装包不能从工程目录直接双击 Inno 脚本——那个目录带保护 ACL，会静默失败、不写日志也不建目录，看起来就像「无法创建目录」。一律输出到 `D:\Build\dist`。
- Inno 的默认目录必须用 `{autopf}`：只装当前用户时不提权，选所有用户时落 Program Files；写死 `localappdata` 会因为提权账户不同而报「无法创建目录」。
- GitHub 上传约 1.4 MB/s，130MB 的 exe 大致 90 秒。
- PowerShell 里 git 的输出走 stderr 会报 exit 1，但实际成功——别被退出码骗了。

## 九、阶段 G：细节收尾与回归（11-01）

### 播放页控件重排（仿苹果播放器）

需求原话是「播放器还是太挡字幕」。改法：

- 底部不再是「一整条黑渐变 + 一排方块按钮」，拆成三块：**贴底细进度线**（交互时变粗、滑块露头）+ **左下播放组**（上一集 / 白色大圆播放键 / 下一集）+ **右下竖排功能列**；
- 右下这一列从下往上：选集 → 换线路 → 倍速 → 静音 → 外部播放器 → 遥控 → 全屏 → 退出；
- **中间整块留空**，字幕压在底部也不会被盖住；
- 按钮底色是深色玻璃而不是白色半透明——第一版用白色，遇上雪景/白底画面等于隐形；
- 焦点名字用绝对定位浮到按钮**左侧**，只在聚焦/悬停时出现，不撑开列宽。

第二轮又调了一次：整列往下压到进度线正上方（离底 `2rem`），底色压薄到 42% 黑 + 16px 模糊，图标自带暗影保证白画面上可读，左下两个切换键统一成同一材质。

> 这里有一条值得记住的方法：改完不要只看截图。先在浏览器里量 `getBoundingClientRect()`，再在**白底压力测试**下看一眼（把视频藏起来垫一层纯白），因为半透明控件最丑的样子只在亮画面上出现。

### 遥控失效（一个藏了很久的契约不一致）

现象：遥控本来好好的，忽然手机扫出来的码打不开；或者手机上写着「遥控已连接」，按了没反应。

根因：遥控会话只活在服务端内存里，App 一重启就全清空。可被控页来取指令时，**安卓服务端回的是 `200 + {"error":"会话已失效"}`，而页面只在拿到 `404` 时才认定码死了**。于是页面抱着死码不放，手机上看着像连着，指令发不到任何地方。

为什么以前没暴露：App 不重启，会话就一直在。那天为了更新版本重装了两次 App、强停重启过，把内存会话清干净，才把它顶出来。

修法（三层）：

1. 服务端会话不存在时回 **404**（并在 body 里带 `"gone":true`）；
2. 被控页与手机遥控页同时兼容老服务的 `200 + error` 答复——判失效不看状态码，看内容；
3. 手机端失效时明确写「遥控码已失效，回到对方页面再点一次遥控」，不再假装连着。

顺带补了一条：`tv.html` / `rc-host.js` / `rc.html` 这些**页面资产改 no-cache**。它们随 App 升级而变，浏览器要是自己留一份旧的，用户看到的就是上一版界面和逻辑（旧 `rc-host.js` 不会换码）。播放流不走这条路由，不受影响。

## 十、架构与取流链路

### 组件

```
浏览器 ─┬─ 电脑 8080（Next.js 15 + Node 22）
        └─ 安卓/电视 8080（Kotlin + 内置 Node 20）
              ├─ /api/*          搜索、详情、代理、历史、遥控
              ├─ /tv  /rc  /qr.js /rc-host.js /rc-nav.js   （电视页 / 遥控页 / 二维码 / 几何导航）
              └─ /hg-api/*  →  短剧内核 8000（签名、取直链、解密、转封装、切 HLS）
```

### 取流链路（红线区）

```
播放器 ── hls.js ──► /api/proxy?url= 分片
                        │  改写：manifest / 子列表 / AES key / init 段全部换成代理地址
                        │  Range 与 206 透传（拖进度不重下整段）
                        ▼
                     源站（带 Referer / UA，跨域与防盗链在服务端解决）
```

**这一条链路上的四个东西一行不改**：`hls` 配置、预取器、分片缓存、`/api/proxy`。任何「顺手优化」碰到它们要先停下来评估，必须能证明起播速度持平或更好。

### 端识别

一个地址按 UA 给不同界面：手机/平板进手机版，电视与电脑进电视版；`?ui=` 可手动覆盖并记 cookie 30 天。踩过的坑：手机上曾因为 cookie 优先于 UA 判断，导致 iPhone 一直进电视版；现在手机上不认这个 cookie，只在地址里显式写 `?ui=tv` 时才给电视版（当次有效）。

### 4. 白底/亮画面压力测试
