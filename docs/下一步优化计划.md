# 下一步优化计划

写于 2026-10-31，版本 1.2.6 / 安卓 1.6。这份文档只回答三件事：**现在做到哪了、下一步做什么、凭什么这么排**。做完一项就往这里划掉一项，不留「计划着计划着就忘了」的清单。

## 一、现在处在哪

| 区块 | 已经稳的 | 还欠的 |
| --- | --- | --- |
| 首页 / 榜单 / 日历 | Netflix 式头图、TOP 10、继续观看、日历、stale-while-revalidate 秒开 | 排序是固定规则，没有按「我看了什么」加权 |
| 详情页 | 全部季列全、演员可点、相似影片、换源 | 选集的「看过 / 未看」区分只有进度条，没有集级标记 |
| 播放器 | 预取器 + 分片缓存 + 代理链路、片头/中段/片尾标记、自动连播、长按 2×、错误恢复、画中画（P 键）、手机手势（横滑进度 / 左右半屏调亮度音量）、按 `?` 呼出快捷键表 | 没有字幕、没有系统媒体键（Media Session）、没有播放质量自检 |
| 遥控器 | 扫码即用、手机长按连发、状态回传、竖音量条、三端方向键同一套算法 | 没有 PWA、没有蓝牙遥控器映射、没有「卡顿自动换源」 |
| 安卓版 | APK 内置整套 Node 服务，手机自己就是服务器 | 后台被系统杀掉后要手动重开 |

## 二、排优先级的三条原则

1. **摩擦优先**：用户每一次「咦，怎么没反应 / 怎么又断了」都比一个新功能值钱。遥控器的三轮迭代基本都是这条撑起来的。
2. **取流红线**：`hls` 配置、预取器、分片缓存、`/api/proxy` 一行不许改；任何优化都要能证明「起播速度持平或更好」。
3. **可验证**：每条优化上线前都要有实测口径（数字或可复现步骤），否则不算做完。

## 三、P0 — 下一步就做（预计 2 轮）

### 1. 播放器「继续观看」闭环
- **现状**：有观看历史，但从首页点进去是重新起播，用户得自己拖回上次的位置。
- **做**：进入播放页时若该片有进度且 > 60 秒、< 95%，先给一张「继续观看 12:34 / 从头开始」的卡片，5 秒无操作自动继续；换源、换集之后位置仍然生效；遥控器的「确定」= 继续观看。
- **验收**：同一部片退出再进，二次起播落点误差 < 2 秒；换源后落点不变；从头开始后历史位置被清。

### 2. 系统媒体键（画中画已经有了，只差把两者接起来）
- **现状**：`P` 键能进画中画，但切到别的窗口后，键盘的播放/暂停媒体键、耳机线控都不管用；画中画窗口里也没有「下一集」按钮。
- **做**：接 [Media Session API](https://developer.mozilla.org/en-US/docs/Web/API/Media_Session_API)——写 `metadata`（片名 / 集数 / 封面），注册 `play` `pause` `seekbackward` `seekforward` `nexttrack` `previoustrack`；按 [Picture-in-Picture API 文档](https://developer.mozilla.org/en-US/docs/Web/API/Picture-in-Picture_API)的说明，画中画里的上一集/下一集按钮正是由这些 Media Session handler 提供的。
- **验收**：Windows 上按键盘媒体键能暂停/继续；PiP 窗口里出现「下一集」并能用；退出 PiP 回到原位、播放不中断。

### 3. 快捷键表（本轮已做）
- 播放页按 `?` 呼出，列出空格/K、J/L、←/→、↑/↓、M、0–9、`,`/`.`、F、P、Esc、Shift+I/O/S/E、Alt+←/→ 十六条；点空白处或 Esc 关闭，面板开着时其他键不误触。
- 剩下的：控制条上给一个 `?` 入口（现在只有键盘能呼出），手机端也能看。

### 4. 字幕
- **做**：支持外挂字幕（源站给 `srt` / `ass` 时转 `vtt`），字幕菜单里可调字号、描边、延迟 ±5 秒；记住上次的样式；遥控器上能开关字幕。
- **风险**：`ass` 的特效字幕只能退化成纯文本，不追特效。
- **验收**：至少两种编码（UTF-8 / GBK）的字幕能正显示出中文；延迟调整实时生效；样式记忆跨集生效。

### 5. 播放质量自检面板（本地，不外传）
- **为什么**：用户反复强调「不能变慢」，靠感觉争论没有意义。
- **做**：记录每次起播的 `manifest → 首帧` 耗时、缓冲次数、平均码率、卡顿时长，只在设置页里给一张表；数据只存本地，可一键清空。
- **验收**：播放三次同一部片能看到三条记录；换回上一版安装包对比，起播耗时差异可量化。

## 四、P1 — 下一版候选

6. **卡了就自动换源**：连续卡顿超过阈值（现有「卡超过 8 秒提示换源」再往前一步）自动尝试下一条线路，失败再退回提示。
7. **连播可视化**：片尾前 30 秒出「下一集 10 秒后播放」卡片，可取消；遥控器上有对应的「下一集」焦点。
8. **片头/片尾标记导入导出**：本地标记库支持导出 JSON、导入别人的，按影片指纹匹配，做成本地版的「共享跳过库」。
9. **遥控器 PWA**：手机扫码页可「添加到主屏幕」，带图标与常驻通知；断网时给出明确的离线页。
10. **蓝牙/电视遥控器按键映射**：安卓电视端把实体遥控器的返回、音量、菜单键接到现有指令体系上（现在只有网页键盘事件）。

## 五、P2 — 观察，不急着做

11. **首页个性化排序**：按本地观看历史给「继续观看 / 猜你想看」加权，先做影子模式（只记录不改变排序），数据够了再打开。
12. **无障碍与缩放**：焦点环对比度、屏幕阅读器标签、字号缩放档位。电视场景下这条其实比想象中重要。
13. **缓存下载可行性**：源站分片多为短时效链接，先做技术验证再谈功能，不做无法兑现的「离线观看」承诺。

## 六、工程与回归

把这三轮靠手工点的测试固化成脚本，每次发版前跑一遍：

| 脚本 | 覆盖 | 现在怎么做 |
| --- | --- | --- |
| `nav-regress` | 三端方向键：正下方优先、横排不串排、一排最左不甩屏、滚动容器能到底 | 手工派发键盘事件 + 记录焦点坐标 |
| `rc-chain` | 手机按下 → 被控页真的动，链路延迟 < 50ms | 真遥控链路 + 时间戳 |
| `state-66` | 选集完整性：66 集全在、下标不错位 | 喂假状态，检查按钮文案与浮层条目数 |
| `player-metrics` | 起播耗时与首帧 | 见 P0-5 的自检面板 |

发布检查单（每次发版照抄一遍）：

1. `tsc --noEmit` + `next build` 双绿；`node --check` 过所有改过的 js。
2. 起播速度：与上一版同片对比，不慢于上一版。
3. 三端方向键与遥控链路回归脚本全过。
4. 安装包静默安装到非 C 盘能启动、源列表不空、不报「错误 5」。
5. CHANGELOG、README、Release 说明三处同步（全部中文，不留片名演员名）。
6. 同一个版本号内替换资产，不为了发版堆版本号。

## 七、风险与红线

- **红线**：取流链路一行不改。任何「顺手优化」碰到 `hls`、预取器、分片缓存、`/api/proxy` 就先停下来评估。
- **字幕与 PiP**：都要求真实的用户手势，遥控器触发会被浏览器拒绝——这类功能必须以「本地点击可用、遥控触发给提示」的方式设计，不要假装能远程开。
- **自检面板**：只做本地记录，绝不上传，避免变成另一种「遥测」。
- **版本节奏**：一轮改完再发，宁可攒着也别一天三个版本号。
