# 手机遥控全员审核（1.2.7 / 安卓 1.7）

上一版把遥控的手感（暂停图标、音量、倍速、拖进度）压到了几十毫秒，但只在「首页 → 播放页」这一条路上验过。
这一轮把**所有会发命令、所有会执行命令的地方**挨个对了一遍，查出 8 处不一致，全部修掉。

## 一、先列清楚「有哪些端」

遥控不是一条链路，而是「两台设备 × 两条通道」的网格。少看一格就会漏。

| 端 | 入口 | 发命令 / 收命令 | 代码 |
| --- | --- | --- | --- |
| 桌面被控（当前页） | 顶栏「遥控器」/ 播放页 / 详情页 / 演员页 / 片名页 | 收（`/api/rs/host` 长轮询） | `app/src/lib/remote-engine.ts` |
| 桌面遥控页 | 手机扫桌面出来的码 | 发（`/api/rs/cmd`） | `app/src/app/rc/page.tsx` |
| 安卓被控（手机版页面） | 顶栏 + 播放器里的按钮 | 收 | `android/.../assets/index.html` + `rc-host.js` |
| 安卓电视被控 | 电视页顶栏 + 播放条 | 收 | `android/.../assets/tv.html` + `rc-host.js` |
| 安卓遥控页 | 手机扫安卓的码 | 发 | `android/.../assets/rc.html` |
| 桌面旧通道（网页版遥控面板） | 另一台电脑打开局域网地址 → 遥控 | 发 `/api/remote/push` | `components/remote-pad.tsx` |
| 桌面旧通道接收端 | 全站常驻 | 收 `/api/remote/poll?role=pc` | `components/remote-sink.tsx` |
| 服务端 | — | 认参数 | `app/src/app/api/rs/[action]/route.ts`、`android/.../RemoteSession.kt`、`WebServer.kt` |

交叉比对的三个表：**发出的命令集**、**执行的命令集**、**服务端认识的参数字段**。三张表对不上的地方就是 bug。

## 二、查出的问题与改法

### 1. 安卓手机版页面：音量/倍速命令全落到默认分支（`index.html`）

`onCmd` 只接了 `ep / line / search / next / prev / fullscreen / ok / back / home`，
`volup / voldown / volset / mute / rateup / ratedown / rateset` 一律落到 `rc-host.js` 的默认分支，
那里直接写 `video.playbackRate`，**没写 `defaultPlaybackRate`**——换集 `load()` 之后倍速被打回 1×。

改法：`index.html` 的 `onCmd` 补显式分支，倍速统一走页面自己的 `setRate(r)`（它同时写默认值、更新播放条文字、记偏好、出 toast）。

### 2. 安卓电视页：音量用旧的加法算法（`tv.html`）

`volup / voldown` 是 `volume + 0.1` 累加，浮点会漂（实测 0.65 → 0.8 → 0.7），且缺 `volset / rateset / rateup / ratedown`。
改法与上一条一致：绝对取整算法 + 解静音 + 倍速过 `setRate()`。

### 3. 两个页面报给遥控器的副标题没有信息量

`sub` 只会返回「正在播放」，遥控页标题下那行小字等于没用。
改成 `第 N/M 集`（播放器内）、`浏览中`（列表页）。

### 4. 指令长轮询失败时 60ms 空转（`remote-engine.ts` / `rc-host.js`）

长轮询的节奏是「有指令立刻返回，没指令挂 700ms」，所以成功路径的间隔只留 60ms。
但**失败路径也套用了 60ms**：服务重启、拔网线、手机切后台受限的瞬间，会以每秒 16 次的节奏打失败请求。

改法：连续失败次数指数退避 `60 → 120 → 240 → 480 → 960 → 1500ms` 封顶，一次成功立刻回到 60ms。

### 5. 状态上报会阻塞指令链路（`remote-engine.ts`）

`tick()` 里 `await reportState(t)`：上报只是锦上添花，但如果这一发 fetch 挂住（网络半死不断），
整条循环——包括**取指令**——就一起停在那里。

改法：改 `void reportState(t)`；`reportState` 内部加 `stateBusy` 闸门（上一发没回来就不叠新的）与 4 秒 `AbortController` 超时。
安卓端 `rc-host.js` 本来就是 fire-and-forget，补上同一个 `stateBusy` 闸门，避免断网时请求越堆越多。

### 6. 详情页 / 演员页 / 片名页：没有遥控入口，引擎也不启动

顶栏里的 `<RemoteHost />` 是唯一调用 `start()` 的地方，而这三页**不渲染顶栏**。
后果：从首页点进详情页还能控（SPA 不重挂），**但直接刷新或从搜索直达就彻底失灵**——会话在服务端活着，页面却没人来取指令。
而这三页恰恰是「躺沙发上挑季、挑集、看演员」最常待的地方。

改法：
- 新增 `components/remote-boot.tsx`，在 `Providers` 层常驻，只做 `start()` + `setHandlers()`，不渲染任何东西（`start()` 幂等，`installNav()` 只提供 `move/ok`、不抢键盘，重复挂载无副作用）；
- 三页顶部返回条右侧各加一个 `<RemoteHost />`，样式跟随该页（黑色渐变条 / 浅色条两套）。

### 7. 刷新 / 重载后会话码丢失，手机上那台遥控器直接断

`S.token` 只在内存里，页面一刷就没了；遥控端还捏着 token 在发指令，被控端已经没人认领。

改法：token 与 url 存 `sessionStorage`（同标签页刷新保留，**关掉标签页即结束**，与面板文案「关掉页面才算结束」一致），
`start()` / `mount()` 时读回并继续轮询。
关键细节：**恢复后的第一条 host 回执不能回放队列里的历史指令**（否则刷新一下页面就自己乱跳），
所以加 `resume` 标记——头一条只用来把 `since` 对齐到服务端当前 `seq`，`cmds` 直接丢弃。

### 8. 旧通道（`/api/remote`）三处没人管

- `remote-sink.tsx` 不认 `menu`（旧面板上那个「菜单」按钮点了等于没按）→ 并入 `settings` 分支（派发 `mfl:rc-settings`）。
- `tv.html` 的 `rcApply()` 不认 `volup/voldown/volset/mute/rateup/ratedown/rateset/seekb/seekf/seekto/ep/line` → 逐条补齐，倍速同样过 `setRate()`。
- 两处 800ms 固定重试 → 同第 4 条，指数退避封顶 1800ms。

## 三、验证

桌面端（`http://127.0.0.1:8401`，真机链路，不 mock）：

| 检查项 | 结果 |
| --- | --- |
| `/title/1`（无顶栏）渲染出「遥控器」按钮 | ✅ 按钮存在 |
| 点按钮出码 | ✅ `http://192.168.2.188:8401/rc?t=42UTS3` |
| token 落 `sessionStorage` | ✅ `mfl:rc-token = 42UTS3` |
| 整页重载后会话被接手 | ✅ `/api/rs/info` 回 `hostAlive: true`、`state.page = /title/1` |
| 重载后**不**回放历史指令 | ✅ 队列里有 `home`，页面仍停在 `/title/1` |
| 恢复后新指令照常执行 | ✅ 发 `back` → 页面回到 `/` |
| `tsc --noEmit`、`node --check rc-host.js`、两个 HTML 的 script 块语法 | ✅ 全部 0 |

安卓端：`index.html` / `tv.html` / `rc-host.js` 逻辑与桌面端同一套，改完过语法检查，随 1.7 的 APK 一起出。

## 四、沉淀下来的经验

1. **发绝对值，不发增量**。音量、倍速都由遥控端本地算出新值再发 `volset` / `rateset`。
   增量在浮点累加下必然漂（`0.1+0.2` 那套），而且丢一条指令就永久偏一格。
2. **倍速必须走页面自己的 `setRate()`**。直接写 `video.playbackRate` 只影响当前这一集，
   `load()` 之后回到 `defaultPlaybackRate`（默认 1），用户以为「倍速坏了」，其实是换集换掉了。
3. **上报与取指令必须解耦**。锦上添花的东西（state 上报、选列表、二维码探测）挂住时不许连累主循环；
   凡是可能永不返回的 fetch，都给 `AbortController` 超时 + 单飞闸门。
4. **所有循环都要有失败路径**。写「有指令立刻返回、没指令挂 700ms」时，顺手把「失败」也当一种返回考虑进去；
   成功路径的紧凑节奏不能复用到失败路径。
5. **一条链路两个通道时，命令集要成对维护**。`/api/remote`（旧面板）和 `/api/rs`（扫码）并存，
   新加一个命令就得同时看两边的接收端，否则旧通道那个按钮就是个摆设。
6. **会话要能跨刷新，但恢复不能重放**。持久化只存 token/url，不存 `since`；
   恢复后第一发回执把 `since` 对齐到服务端 `seq` 并把队列丢掉——「刷新一下页面自己往前跳一屏」是最难解释的那种 bug。
7. **审核按「端 × 能力」列网格再逐格对**。只测主链路（首页→播放页）会漏掉所有「直达页」和「旧通道」，
   而用户真正抱怨的往往就是这些边角。

## 五、没动的东西

取流链路一行没碰：`hls` 配置、预取器、分片缓存、`/api/proxy`、短剧内核与吐流改造保持原样。
`remote-nav.ts` 的焦点走格子逻辑也没动——它本来就是被动 API（`move/ok/clear`），不注册任何键盘监听。
