# MFlixTV

**一个装在自己设备上的影视聚合播放器。** 把开源的影视聚合站点 [LibreTV](https://github.com/LibreSpark/LibreTV) 做成能双击安装的桌面应用、能装到电视上的安卓应用；Netflix 风格的首页与资料页、影片和演员一起搜的检索、换集换源不黑屏的播放器，外加一个短剧专区。

它最有意思的一点是：**装在一台电脑上，同一个网络里的手机、平板、电视什么都不用装，用浏览器打开一个地址就能一起看**（下面第二节）。

当前版本 **1.2**（Windows 安装包 **1.2.2**）：安装包 `MFlixTV-Setup-1.2.2.exe`、安卓包 `MFlixTV-android-1.3.apk`。1.2 把遥控改成**扫码即用**：任何一端（电脑网页、手机网页、电视）点右上角遥控按钮就出二维码，另一台手机扫完直接变遥控器，**只控制出码的那一个页面**；1.2.1 把遥控面板的状态点改成「绿=在线 / 红=对方关了」（原来两个状态都是品牌红，等于没指示）；1.2.2 把遥控真正做成**电视遥控器**：首页 / 详情页 / 搜索结果也能用十字键一格一格走、确定键进片，返回逐层退（不再等于浏览器后退），上集下集换成「选集」网格 + 「线路」，并修掉二维码面板关不掉（层级被首启向导压住）和安卓 App 内点遥控不弹码（面板样式用了老内核不认的写法）；1.1 加了片源停用与导出导入、电视端设置、一台设备多使用者与家长控制；1.1.1、1.1.2 只修安装程序（装到哪都不会再报「无法创建目录」——1.1.2 起安装包也不再生成在带保护 ACL 的工程目录里，从那种文件夹双击会静默失败）。

## 一个程序，三端可用

MFlixTV 不是一个「客户端 + 服务器」的两段式软件，它就是**服务本身**：装在哪台设备上，服务和界面就一起跑在那台设备上。

| | 桌面安装版 | 安卓版 | 网页版 |
| --- | --- | --- | --- |
| 形态 | Windows 安装包，双击启动 | 一个 APK，手机 / 电视通用 | 浏览器打开，什么都不用装 |
| 服务跑在 | 这台电脑 | 这台手机 / 电视 | 打开它的那台设备的服务 |
| 界面 | 桌面界面 | 手机竖屏 / 电视 10 英尺界面自动切换 | 自适应 |
| 典型用途 | 主力看片、管理与配置 | 沙发上看、手机上看短剧 | 手机、平板顺手打开电脑上那份 |

### 同一网络用网页版访问（安装版最实用的能力）

1. 在电脑上打开 MFlixTV（启动后自己开一个本机服务，默认 `8080` 端口）。
2. 顶部右上角显示这台电脑在局域网里的地址，形如 `192.168.x.x:8080`。**点它一下会弹出面板**：二维码 + 可复制地址。
3. 手机 / 平板 / 电视连**同一个 WiFi**，相机扫码或直接输入地址，就是完整的网页版：搜索、详情、播放器、短剧专区、追剧日历都在。
4. 第一次打开要输这台电脑上设的访问密码，之后同一个浏览器会记住。

为什么值得用：

- **不用装 App**：iPhone、iPad、安卓手机、电视浏览器、另一台电脑，有浏览器就行。
- **不用投屏**：投屏是把电脑画面推过去；这里是对方自己解码播放，画质和操作都更顺。
- **不占对方空间**：看的是这台电脑上的片源与缓存。
- **记录各用各的**：手机上看过的进度留在手机，电脑上的记录不跟着变。

会踩到的坑，先说清楚：

- 手机和电脑必须在**同一个局域网**（同一个路由器 / 同一个 WiFi）。用流量或在别人家的网络上打不开。
- Windows 防火墙第一次会问「是否允许此应用通信」，选允许，否则手机连不上。
- 这台电脑有多块网卡（有线 + 无线 + 虚拟网卡）时地址不止一个，面板里可以切换，选手机所在网络对应的那个。
- 电脑睡眠后服务会停，别的设备就断了。
- 安卓版自己带着服务：装到手机上，手机开着的时候，同一个网络里别的设备访问「手机 IP:8080」也能用。

## 功能

**检索：影片和演员一起搜**

- 一条搜索框同时打三类数据：自己的点播源（并行流式返回）、豆瓣条目、豆瓣演员
- 搜人名也能出结果：输入姓氏片段 → 命中对应演员，点进演员页看全部作品（联想命中不了时，会退化成「按人名搜影片 → 演职员表模糊匹配」，所以给名字片段也找得到）
- 跨源同名影片自动合并成一张卡，展开可直接比较各来源的画质与速度

**资料页：所有片名、人名都点得动**

- 采集源资料页 `/detail/<源>/<片>`：海报、年份地区类型、简介、导演主演、播放源、剧集一页看完——原来的「播放前详情弹窗」已经并进这一页
- 豆瓣资料页 `/title/<id>`：评分 / 简介 / 演员（可点进演员页）/ **相似影片** / 页内直接换源选集
- 导演、主演渲染成名字胶囊，点一下就用这个名字再搜；换源面板有「看资料」，观看历史每条也有「资料」，不用先进播放器

**扫码当遥控器：另一台手机扫一下就变遥控器**

- **页面上点右上角的遥控按钮**（电脑端顶栏「遥控器」、网页版手机端最右边的手机图标、电视端导航栏「遥控」），当场出二维码；不用进设置、也不用先知道这台机器的 IP。播放页里也有一个入口（手机端播放器右上角、电视端底部那条「遥控」），正在看片时不用退出来才能出码
- 另一台手机（安卓 / 苹果都行）扫码直接进遥控器页面：播放 / 暂停、快退快进 10 秒、拖进度条、音量与静音、**选集**（点第几集就播第几集）、**线路**（网页版接到「换源」面板上，安卓 / 电视端是真切换）、方向盘 + 确定、返回、回首页；不用装 App、不用密码
- **遥控的是整个页面，不只是播放器**：十字键走的是**几何导航**——往哪个方向按，就在那个半平面里找「最近且最正对」的可点元素，首页海报墙按右走下一张、按下换一行，确定键当场点进去，选中项有红色描边；左右只在同一行里走，不会在一行末尾窜到右上角的图标上
- **返回是逐层退**：先退全屏 → 再关最上层的浮层（播放器内的选集 / 换源面板、抽屉、二维码面板）→ 都没有才退一层页面，不会一点返回就跳出站点
- **一张码只管一个页面**：同一台机器开了两个标签页、或者电视和手机各放各的片，各自出各自的码，互不串台；被控的那个页面关掉，这张码就失效
- 遥控器上能看到对方在放什么、放到第几集、进度多少，播放键跟着实时状态变
- 二维码是页面自己画的（内置 `qr.js`，byte 模式 + 纠错 M），不引第三方库、不走 CDN——连不上外网的机顶盒也能出码；遥控码 6 位、去掉了容易看错的 `0 O 1 I L`，只在内存里活 30 分钟，不落盘、不外发
- 设置页里那个「遥控这台设备」还在（整台机器一条队列：手机打开电视地址就能控，连搜索都能代劳），两个互补
- 电视端快进改成 **10 / 15 / 30 秒** 可选，同一方向 0.6 秒内连按三次直接 ×3 跳

**片源健康：能停、能导出、能带走**

- 设置里每个源显示延迟、通不通、是否已停用；点一下停用，再点一下启用
- 停用的源不参与搜索和首页取数；万一全停光了会自己退回全集，不会把界面锁成空列表
- 「导出」把源清单和停用清单压成一段 JSON，「导入」粘回去就还原——换设备、给朋友的机器用，一步搬完

**多使用者与家长控制**

- 「谁在看」可以建多个使用者，切换时把「继续观看、我的列表、焦点位置」整块换掉，各自独立
- 家长控制：设 PIN、设儿童屏蔽词、设生效时段；命中屏蔽词的内容从搜索、首页行、今天更新里直接不出现，播放前过时段会先要 PIN
- 电视没有键盘，配置在电脑或手机上设好，一键同步到电视；电脑端点播放遇到时段也会先弹 PIN 输入

**播放：观影体验优先**

- 播放内核 ArtPlayer + hls.js：前向缓冲 60s（开缓存 120s）、首片预取、按播放器尺寸选档、分片重试 8 次
- 换集 / 换源**不黑屏**：切换瞬间把上一帧抓成遮罩，新分片进 buffer 才淡出
- 换源面板标出**最快**源（有集数且详情接口最快），当前源本来就最快时直接说「不用换」
- 手势：双击左 / 右 ±10 秒、长按 2 倍速；快捷键 空格 / ←→ / ↑↓ / F / Alt+←→
- 广告分片过滤、跳过片头片尾、倍速记忆、断点续播、自动连播

**首页：Netflix 那套结构**

- 头图 billboard（本周推荐 + 播放 / 更多信息 + 右侧候选封面）
- 搜索框下面是热词胶囊，点一下就搜；横向行统一成一套可滑动的 rail（到头箭头置灰）
- 继续观看（红色进度条 + 「第 N 集 · 剩余约 X 分钟」，点一下按上次位置续播）
- **本周追剧（追剧日历）**：一条周一…周日的日期条，每格写当天的更新部数与分类；下面按分类列出这一天更新了什么，可「只看我追的」（取自己的观看记录 / 清单），点「整周」进 `/calendar` 全屏周表——翻周、切分类、加载更多，日期条数字与列表始终同一份数据（同一天同一部只算一条）
- 本周 TOP 10（大数字排名）、分类推荐网格、相似影片行

**短剧专区（本项目新增）**

- 两层导航：真人剧 / 漫剧 / AI短剧 → 各自的推荐 / 热播 / 新剧
- 观看历史按「剧 + 集」记进度；**换源续播**只往前挪 10 秒（不同源码率不同，往后挪必然漏剧情）
- 收藏 / 已看标记 / 连播倒计时 / 倍速记忆；记录只存本机（这台设备看过的就是这台设备的，别的设备是另外一份）

**桌面体验**

- Windows：自带 Node 运行时与 ffmpeg，装完双击即用；托盘常驻（启动 / 停止 / 重启服务、打开网页、复制访问密码、复制局域网地址）
- macOS：解压后双击 `.command` 启动
- 局域网观看：[一个程序，三端可用](#一个程序三端可用)，右上角地址点一下出二维码，手机扫一下就能看
- 每天 / 按需检查更新：拉短剧内核新版、按拉流速度重排可用点播源

## 快速开始

### Windows（推荐）

1. 打开 [Releases](../../releases) 下载 `MFlixTV-Setup-x.y.z.exe`
2. 安装（可选桌面快捷方式），双击 **MFlixTV**
3. 浏览器自动打开 `http://localhost:8080`，默认密码 **`MFlixTV`**
4. 退出：托盘图标右键 →「退出」

> 未做代码签名，首次运行 Windows 会提示「未知发布者」，点「更多信息 → 仍要运行」。

### macOS

1. 下载 `MFlixTV-macOS-arm64.zip`（Apple 芯片）或 `x64` 版本
2. 解压后双击 `启动MFlixTV.command`
3. 首次可能被 Gatekeeper 拦：右键 → 打开，或执行 `xattr -dr com.apple.quarantine ./MFlixTV-macOS`

### 桌面快捷方式（可选）

`tools\start.ps1` 幂等启动：已经在跑就只打开浏览器，没跑就依次拉起短剧服务(8000)与主站(8080)，等就绪后再开页面。

```powershell
# 建一个指向它的快捷方式（目标填这行，图标用 packaging\app.ico）
powershell -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File tools\start.ps1
```

日志：`logs\start.log`。装过安装版的话，脚本会优先直接拉起托盘程序。

### 打开是空白 / 提示「此网页无法正常运作」

## 短剧专区

入口：顶栏「短剧专区」，或首页的入口卡片。

**数据来源说明**

上游（字节系）的接口里，只有「漫剧」开放了官方榜单接口；真人剧与 AI 短剧的目录接口目前返回空。因此：

| 体裁 | 数据来源 |
| --- | --- |
| 漫剧 | 官方三榜（推荐 / 热播 / 新剧） |
| 真人剧 | 关键词聚合搜索 + 上游 `content_type=1` 精确过滤（真实拍摄） |
| AI短剧 | 上游 `content_type=1004` 且排除官方漫剧榜条目（合成画面） |

> `content_type` 这个字段是上游返回的体裁标识，最初的复刻项目把它丢弃了，本项目打补丁透传（见 `hongguo/PATCH.md`）。

**播放链路**

```
MFlixTV 页面 → /hg-api/* → 本机第三方内核 hongguo-web(127.0.0.1:8000)
                ↓
             内核自行完成取流与格式转换 → 以 mp4 形式回到播放器
```

- 同源转发：浏览器只跟 8080 打交道，不开额外端口、不撞 CORS
- 首播需 10–20 秒（取流 + 本地格式转换），之后同一集命中缓存秒开
- 缓存上限 120 集，自动淘汰最旧的

## 安卓版（APK）

桌面这套界面和播放能力，做成一个**独立 App**：装到手机上打开就能用，不需要连着电脑；服务端跑在手机本机，同一 WiFi 的电脑、平板打开 `http://手机IP:8080` 看到的是同一套页面。

- **首页**：顶部是 **Netflix 式整屏大图轮播**——5–8 部片横滑，滑到哪部整页背景就模糊成哪部的海报，片名 / 年份·类型 / 主演跟着换；有观看记录时推「因为你看了《X》」的同类片，没有就用最近更新。下面按电脑端的分类入口排：**最近更新 → 电影 → 剧集 → 短剧 → 综艺 → 动漫**（分类 id 按每个源自己的分类表解析，不写死）；六行并发抓取，10 分钟缓存并落盘，第二次打开秒出（过期先出旧图再后台重建）
- **继续观看 / 我的列表**：看过就自动进「继续观看」，海报底部一条红色进度，点一下直接回到那一集那一秒；「我的列表」收藏同样在首页第一屏，记录只存本机
- **追剧日历**（0.15）：首页大图下面一条周一…周日的日期条，每格写当天的更新部数，今天描红、选中是红色实心；下面就是这一天更新了什么，点「整周 ›」进全屏周表——翻周、切分类（全部 / 电视剧 / 电影 / 动漫 / 综艺 / 短剧）、只看我追的（取本机观看记录与清单）。日期条的数字与列表出自同一份数据，同一天同一部只算一条，不会出现「条上 6 部点进去 4 部」；进页面先出本地快照再后台刷新，断网也看得到上次的周表
- **详情**：海报 + 年份 / 地区 / 类型 / 备注，简介可展开；**主演名字可点**（点了直接搜这个人），选集下面自动列出**同系列的全部季/部**，多线路切换、分集四列网格，记住上次看到第几集
- **跨源线路汇总**：一部片只有在同一个源里才有几条线路，所以详情页会拿片名去别的源找同名片，把 2–5 个源的线路**并成一张表**（每条标源名，如「线路 3 · 魔都」），线路从一两条变成七八条不再是碰运气
- **播放**：包内自带 hls.js，m3u8 与 mp4 都能播；**点播放先亮一段 MFlixTV 红渐变色标**（第一帧出来就撤，连播不重复闪）；没画面时不再出现浏览器白框播放三角——中央是 MFlixTV 字标占位；控制条是 `暂停 · 倍速 · 选集 · 线路 · 下一集`——**选集抽屉**列当前线路全部剧集，**线路抽屉**直接换源并停在同一集继续播；右下角另有 **设置 / 画中画 / 网页全屏 / 全屏** 四个键（设置面板里能改倍速、关自动连播、从头播、复制地址）；拖动、自动连播，退出恢复竖屏，播放位置本地记忆
- **局域网访问也对齐电脑端**：别的设备打开 `http://手机IP:8080` 时，搜索页是一排十几张小卡的平铺网格（手机上仍是 3 列）、影片资料页居中限宽 1024px 双栏排版、播放器四个功能键同样可用
- **全屏与横屏**（0.15）：右下角「全屏」键走原生桥——真转横屏 + 收起状态栏 / 导航栏 + 屏幕常亮，再点回竖屏；旋转键是开关（横 ↔ 竖）。WebView 的 HTML5 全屏也补上了 `onShowCustomView`，`<video>` 自带的全屏键、返回键退全屏都能用。以前这键只弹一句「WebView 不支持系统全屏」、也不转横屏，属于真 bug（浏览器里打开同一个地址是全屏正常的，因为浏览器自己实现了全屏）
- **iPhone / iPad 看网页版也能真全屏**（0.16 / 0.17）：别的手机用浏览器打开 `http://手机IP:8080` 时，iOS 的 Safari 和 Chrome 都没有元素级全屏 API（原来只会弹一句「不支持系统全屏」）。现在播放器全屏分三层——App 内走原生桥，电脑和安卓浏览器走标准全屏 API，iPhone / iPad 走 `<video>` 自带的 `webkitEnterFullscreen()` 系统全屏（横过来就是满屏）；万一机芯不给，600ms 后自动兜底成「页面内铺满 + 强制横屏」。iOS 上同时优先原生 HLS 硬解（更快更省电），**原生拉不动会自动退回 hls.js，不会出现「这个地址播不了」卡死**；代理返回分片时也按扩展名补 `video/mp2t` / `video/mp4` 类型，Safari 认这个
- **电视版 TV 界面**（0.18）：**同一个 APK**，装到电视 / 电视盒子上会自动认出并进 10 英尺界面（Leanback / `UI_MODE_TYPE_TELEVISION` / 无触摸屏任一命中；也可 `adb shell am start -n com.mflixtv.app/.MainActivity --ez tv true` 强制），装在手机上还是原来的手机界面。顶部横排文字导航（首页 / 电影 / 剧集 / 综艺 / 搜索）；焦点在海报上滑动时整页背景与片名跟着换（停 240ms 才换，快速滑动不闪），焦点卡放大 1.16 倍 + 白描边 + 红辉光、同排其它压暗；详情页剧集是 16:9 卡片 5 列平铺，回车直接播；搜索用方向键走字母键盘，出结果后热门搜索自动收起。遥控器方向键 / 回车 / 菜单键由原生 `dispatchKeyEvent` 转给页面（WebView 自己那套一次会动两格），返回键分层退（播放器 → 详情 → 首页）。电视浏览器或电脑上想试电视界面，开 `http://手机IP:8080/tv`
- **播放记录按设备独立 + 记录体验全端对齐（0.35）**：以前短剧的记录会推到服务端、进页面再拉回来合并，结果同一台电脑上安装版和别的设备开的网页版**互相串记录**；现在彻底不连服务端，记录只写本机 localStorage，这台设备看过的就是这台设备的，别的设备是另外一份（电视端 / 手机端的记录本来就在本机，这次把角标写成「本机 N 部」说明白）。同时修掉一个真 bug：电脑端点播**换集时会把上一集的进度带到新一集**（只在「新位置 > 10 秒」才更新），「继续观看」显示「第 4 集 · 已看 80%」点进去却从头开始——现在换集即重置；并且**真的播起来（>3 秒）才建记录**，不再一点开就留一条 0% 的空记录。首页「继续观看」把**短剧记录也收进来**了：按最后观看时间混排，短剧卡写「短剧 · 第 N 集 · 剩余约 X 分钟」，点一下跳回短剧页那一集那一秒；每张卡右上角悬停出现 **×**，删记录不用进面板。电视端记录能删了：焦点停在记录卡上按**菜单键**（Shield 这类没菜单键的用**长按确定**）就删掉这一条，焦点自动交给旁边那张卡；设置页新增「本机观看记录 N 部」，按一下变「再按一次清空」再按才真清，只清观看记录、我的列表不动。手机端记录卡左上角多一个小圆 ×，点它只删这条记录。播放链路（hls / 预取 / 分片缓存 / 代理）一行没动
- **播放器照着苹果那套重做（0.34）**：底部那条「整条黑渐变 + 一排方块键」换成一整块**悬浮毛玻璃面板**——左右各留 2.4rem、离底 1.8rem、1.4rem 大圆角，`rgba(26,26,28,.5)` + `blur(40px) saturate(1.8)` 亚克力质感，配一道发丝描边和顶部内高光；老机芯不认 `backdrop-filter` 自动退回九成不透明纯色，观感不塌。中间是**白色实心圆**的播放 / 暂停键（图标跟着 `play`/`pause` 事件同步，不会在播却显示三角），两边是圆形的上一集、下一集，右边一整排胶囊 `选集 · 1.0× · 外部播放器 · ✕`，中间一枚发丝竖线隔开。进度条变细、纯白实心、末端一枚圆形滑块——顺带修掉一个真 bug：滑块以前因为 `#played` 少了定位基准，一直画在**轨道最右端**，现在落在已播末端（真机 00:20/3:23:13 在最左、mock 46% 在 46% 处）。焦点是 Apple TV 那套手感：白底黑字 + 轻微放大 + 外圈白环，播放键本身是白的，聚焦时先垫一圈深色再套白环，压在亮画面上也看得见。**选集 / 倍速面板**不再是黑底盖满屏，而是长在播放条同一个位置、同一块毛玻璃里——正在看的那一集用一枚细白环表示、焦点才是白底，两者不再长得一样；面板打开时播放条自动收起。线路名也美化了：技术名（`lzm3u8` 之类）显示成「线路 2」、有源名写「线路 2 · 源名」，详情页线路条 / 播放条副标题 / 自动换线路提示三处统一。手机端网页播放器同步换这套：进度条用渐变画出已播白段 + 15px 白圆滑块、白色播放键、毛玻璃胶囊控制条、圆角倍速弹层。遥控器操作没变（长按确定或菜单键进条、左右走、回车选、返回收），1080p / 720p 都量过：面板高 175 / 118、播放键 78×78、底距 24；返回原地还原、自动换线路、两条全挂提示、手机端换线路四组回归全 PASS，播放链路（hls 配置 / 预取器 / 分片缓存 / `/api/proxy`）一行没动，起播与 0.33 持平
- **播放失败自动换线路（0.33）**：线路挂了不再只是糊一句「按返回换一条线路」。内核报错（404 / 分片打不开 / 编码不支持）**立刻**换下一条，纯黑屏没画面的 12 秒换；按详情页那张跨源线路表的顺序往下试，**停在同一集**（按集名对，对不上才按序号），最多试 4 条、同一条不试两次，同一秒连报的重复信号只算一次所以不会一秒连跳三条；**只在「这一集还没出画面」时换**，已经播起来了再切会把进度丢掉，那种情况只提示。换的时候右下角弹一句「这条线路不通，已自动换到「线路 X」」，播放条上的线路名跟着变，「继续观看」记的线路也一并更新（不然下次续播还指着那条死的）。全都换不动才说话，并说清试过几条：「这条线路 12 秒还没画面（已自动换过 1 条线路）」。mock 实测：首条挂掉 0.4 秒换到第二条出画面、线路都正常时不换不误判、两条全挂只换一次并 12.2 秒出提示；Shield 真机起播正常无回归
- **片源自动测速 / 后台维护 / 没源自己找回来（0.32）**：每次体检记下每个源的**延迟、返回条数、连续失败次数**，首页每一行与搜索按延迟从快到慢取源（真机实测：豪华 293ms → 非凡 373ms → 百度云 556ms → … 8/12 可用），连续失败 3 次的源沉到末尾不再参与取源、但不会从列表里删掉。体检缓存 30 分钟，过期后先给上次结果再后台重测；启动时补一次、常驻服务每 30 分钟敲一次。**一个源都不通时会自己去把源找回来**：按 jsDelivr → fastly → GitHub 原始链接 → ghproxy 镜像的顺序拉仓库根目录的 `sources.json`，合并去重写回本地再重测；拉不到就什么都不做，本地源原样保留。电视端设置页多一行「片源体检 9/12 · 最快 无尽 944ms」，按一下当场重测；手机端「源站测速」按延迟列出每个源，旁边是「重新获取片源」
- **首屏整行可见 + 返回原地还原（0.31）**：首页大图以前写死 68vh，真机上第一行卡片底沿会掉出屏幕（1080p 多 38px、720p 多 26px），刚打开电视只能看到半张卡。现在按实测算——先按 68vh 摆好，量第一张卡的底沿，多出来多少就收多少（下限 0.44vh，矮窗口不会把片名顶掉），换分辨率 / 转屏 / 改 DPI 自动重算；1920×1080 收到 686、1280×720 收到 454、4:3 本来够就不动，三种形态实测整卡可见。另外，在第五行点开一部片再按返回，不再被弹回顶部：滚动位置和焦点卡都原地还原（记录行重建过就按片名重新认一次，还原时临时关掉「焦点自动滚进视野」免得位置被自己滚跑）
- **电视端「继续观看 / 我的列表」+ 追剧连播（0.30）**：电视界面首页第一行不再是分类，而是**你这台机器上没看完的片子**——海报底部一条红色进度，上面一行「第N集 · 剩46分」，按一下**直接接着播**，自动找回上次的线路、集数、时间点（按集名优先认，对不上才退回序号），不用再进详情页翻选集；详情页多出第四颗按钮「+ 我的列表」，加过的会亮着，列表同样单独一行。一部没看过时这一行整个不出现。设置页新增两项可点设置，遥控器按一下切一档、不用输数字：**跳过片头**（关闭 / 30 / 60 / 90 / 120 / 150 / 180 秒，默认关闭，因为会真的挪播放位置）和**片尾提前**（关闭 / 20 / 30 / 45 / 60 秒，默认 45 秒，只提前把「接下来播放」叫出来、不动播放位置）。跳过片头只在**新起播**时生效，这一集本来有记录就优先续播、不被片头跳过打断；判断时长要「连续两次读数一致」才动手，刚拿到元数据时读到 0 或半截不会误判。播放中每 5 秒记一次位置，切后台、关页面、退出播放器、按 Home 都补记，退出即刷新首页那一行。手机端的播放设置面板同步加了这两项，与电视端共用同一份设置
- **拖进度条看时间 + 倍速面板（0.29）**：进度条能点能拖（电视遥控左右仍是 ±10 秒），拖的时候上方冒一个「当前时间 / 总时长」气泡，跟着手指 / 滑块实时走，松手 1.2 秒后自己消失；气泡位置按屏幕算，拖到两头会往回收，不会顶出屏幕（1080p / 1280×720 / 1024×768 / 竖屏 390×844 / 横屏都量过）。倍速从「点一下轮一档」换成面板：7 档一眼选，当前速度高亮，选过的速度会记住（换集、换片、重开 App 都还是那个速度，写 `defaultPlaybackRate` 所以新一集 load 之后不被打回 1x）。另外，**Shield TV 的遥控器没有菜单键**，按钮条以前等于摸不到——现在**长按「确定」键**就能呼出（原生侧数按键重复次数，不给正常按键加延迟），菜单键仍然可用，第一次进播放页会提示一次
- **开机自启 / 常驻 / 外部播放器接力（0.28）**：开机广播后先起前台服务（局域网立刻可用），电视 / 盒子上再把界面直接拉起来；另有 15 分钟一次的循环闹钟自愈，服务被系统清掉会自己回来。外部播放器不再「一集一跳」：服务端 `/api/list.m3u` 把当前线路从这一集起的若干集（最多 10 集）拼成播放列表，条目全走本机 `/api/proxy`（直链塞列表会被源站拦成「一直转圈」），播放器自己连播下一集；WebView < 70 的老盒子第一次打开就自动设为外部播放器。从播放器按返回回到 App 会弹「接力卡」：用本机播这一集 / 换条线路 / 下一集（外部）/ 收起
- **电视顶栏显示访问地址（0.27）**：电视界面的右上角固定显示「手机访问 192.168.x.x:端口」，端口取服务端回报的**真实端口**（盒子上 8080 常被预装投屏 / 遥控服务占着，会自动顺延到 8081，显示的就是能直接打开的那个），每 60 秒跟一次 `/api/status`，换网络自己更新，没网显示「未联网」
- **老盒子的播放流畅度（0.26）**：同一路 m3u8 在斐讯 N1（Android 7.1 / WebView 52）上，应用内播放是 JS 解封装 + 软解，进程 CPU 会顶到 30% 以上并掉帧；把地址交给系统里的硬解播放器（MX Player / VLC / 盒子自带）后 CPU 只有 0~1%，1080p 全程顺滑。所以新增了**外部播放器**：详情页第三颗按钮、播放页按钮条第 6 颗，以及设置里的「播放方式 → 外部播放器 · 硬解更顺」（打开后点任何一集都直接进外部播放器）。交给外部播放器的是本地 `/api/proxy` 地址，Referer 与 m3u8 分片重写都在服务端做，不会被源的防盗链拦；交出去前先暂停本页并停掉 hls 拉流，不抢带宽。同时修掉「播放页按钮条遥控器走不到」——以前方向键被快进 / 切集占满，底下七颗按钮形同摆设，现在按**菜单键**进按钮条：方向键移焦点、回车执行、返回退出条子。老 Android 盒子上的白屏 / 闪退也一并根治（`getWebChromeClient()` 是 API 26 才有的方法，按 API 34 编译在 API 25 上跑直接 `NoSuchMethodError`；`scrollBy` 老内核只认两个数字；兜底页会写出实际检测到的 WebView 版本并给安装指引，`tv.html` 顶部还有一道 `fetch / Promise / WeakMap` 能力闸）
- **电视端体验（0.21）**：修掉「播放时右边少一截、下面少了点」——病根不在视频，而在详情页背景图用 `left/right:-6%` 外扩把**文档撑宽了 90px**，`window.innerWidth` 于是从 960 变 1050，铺满四边的 `position:fixed` 播放器跟着铺成 1050×591，底部「暂停 / 上一集 / 下一集 / 选集 / 倍速 / 退出」六颗按钮整排落到可视区外（y 549~572，屏幕只到 540）。外扩改由 `transform: scale(1.12)` 承担（不参与布局）+ `overflow-x:hidden` 兜底后，文档宽度回到 960，播放器 960×540，按钮组下沿 521，留 19px 余量。同时在 1920×1080 / 1280×720 / 960×540@2x / 4:3 1024×768 / 4K / 21:9 六种屏幕形态上验过：零横向溢出、零控件裁切；小屏字号加了 `max(8px, 1.0416667vw)` 下限。界面继续往 Netflix TV 版收：导航回到纯文字（未选中灰、选中纯白 + 微放大）、大图区 68vh、片名 3.35rem、方角按钮与海报、焦点改纯白描边 + 1.13 放大
- **电视端体验（0.20）**：海报全部走本机 `/api/proxy` 转发（采集站图床拦外链，直连在盒子上就是一片灰），取不到自动退回直连再退渐变底；播放器没画面时铺黑底 MFlixTV 字标 + 「正在接通线路…」，牌子只在真正出画面或出错时才撤（以前 2.6 秒就撤，WebView 会把未解码的视频画成白框 + 播放三角）；顶栏右上角补回 **搜索 / 设置**，设置面板显示版本、WebView 版本、界面模式、屏幕、局域网地址、机型，并能重新载入 / 清空缓存；导航胶囊、卡片与按钮统一圆角，支持的机器上顶栏与抽屉用毛玻璃
- **老盒子也能跑**（0.19）：电视界面原来用了 `aspect-ratio` / flex `gap` / CSS Grid / `inset` 这些新内核才认的写法，Android 7.1 的旧 WebView（斐讯 N1 这类 S905 机器常见）会直接散架。现在每一样都有 `@supports` 兜底：海报与剧集卡改定高、间距换回 `margin`、字母键盘和搜索结果退回 `inline-block`，布局一模一样。WebView 主版本 < 85 或 CPU 核心 ≤ 2 时还会自动进**轻量模式**（去掉大半径模糊与重阴影，滚动不卡），也可用 `?lite=1` / `?full=1` 手动指定
- **图标**：桌面图标与电脑版同一个（红底白 M），Android 8+ 走自适应图标，圆形 / 圆角 / 方形启动器都正常；电视端另有 320×180 横版 `tv_banner`，Android TV 启动器里是正经海报位
- **m3u8 代理重写**：manifest 里的分片、子播放列表、AES 密钥、init 段全部改写成 `/api/proxy?url=…`，由手机本机的服务端转发——跨域和防盗链都不再挡路；Range / 206 透传，拖进度条可用
- **设置页**（顶栏齿轮）：局域网地址 / 本机地址分两行显示，一键复制局域网地址；**点播源可增删并保存**（源站挂了删掉、有新接口加进来，改完立即生效并持久化）；一键恢复默认源；代理、逐个源自检、清空本机播放记录、**息屏常驻开关**
- **息屏常驻**（0.14）：手机锁屏后前台服务还在、网卡也连着，但 CPU 会被系统挂起，局域网设备来拉分片就没人应答——表现是「手机上还在播，别的设备一锁屏就播不动」。现在服务持 `PARTIAL_WAKE_LOCK`（不亮屏、只醒 CPU），默认常驻；嫌耗电可在设置里切「省电模式」（只在有播放流量时醒着）。另有 60 秒看门狗（HTTP 线程挂了自动重建）、划掉最近任务自动拉回、WiFi 低延迟锁
- 搜索覆盖全部源，片名和演员都能命中，结果按年份从新到旧；**同一部片在多个源的结果会合并成一条**（卡片标「N 个源」），结果页有「← 返回首页」，卡片是海报 + 下方片名 + 年份·类型

**自己打包**

```bash
cd android
./gradlew assembleRelease    # 产物：app/build/outputs/apk/release/app-release.apk（正式签名）
```

需要 JDK 17、Android SDK 34（`local.properties` 里写 `sdk.dir`）；**最低 Android 7.0（API 24），不限制 CPU 架构**（0.13 起是通用包，arm64 / 32 位 / x86 都能装，包体积 2.8 MB）。正式签名用仓库外的 `android/keystore/mflixtv.jks`（不进版本库），没有这个文件时自动退回 debug 签名仍能出包。装之前先在系统里允许「安装未知应用」；从旧 debug 包升级要先卸载（签名不同）。

**装不上 / 一装就闪退**：0.13 已经处理掉两个最常见的原因——包里 42 MB 的 `libnode.so` 残留（会让 32 位和多架构机型被判不兼容）、WebView 渲染进程被杀。如果还有问题，设置页「关于」里现在能看到**机型 + Android 版本 + WebView 版本 + 上次异常**，崩溃堆栈在 `Android/data/com.mflixtv.app/files/crash.log`，把这两处发出来就能直接定位。

## 点播源与可用性排序

内置一批苹果CMS 协议的候选接口，另外每次体检会**在候选列表中重新探测并排序直连接口**：

```
内置候选池(24) + 当前配置 + 远程列表(qist/tvbox、gaotianliuyun/gao)
   ↓ 分批并发探活（关键词「庆余年」+ 校验标题真的命中，防止"假搜索站"）
   ↓ 已知快源优先（按实测拉流速度白名单）
   ↓ 只保留 6 个 → 写回 .env
```

**为什么是 6 个、为什么按拉流速度排**：搜索快 ≠ 播放快。实测中有的站搜索 600ms 但拉流只有 18KB/s，播起来必卡。白名单在 `tools/update.ps1` 的 `$FAST_HOSTS`。

手动体检：托盘菜单 →「检查更新（短剧内核 + 点播源）」；或命令行

```powershell
powershell -ExecutionPolicy Bypass -File tools\update.ps1 -Part sources
```

测自己的源速度：

```powershell
powershell -ExecutionPolicy Bypass -File tools\bench-sources.ps1
```

## 更新机制

`tools/update.ps1` 支持三种模式：

| 参数 | 作用 |
| --- | --- |
| `-Part kernel` | 拉取 [hongguo-web](https://github.com/sunnysky123/hongguo-web) 最新源码，备份旧内核（`src.bak-时间戳`），重新打 `content_type` 补丁，重启短剧服务 |
| `-Part sources` | 点播源体检 + 从公开列表补新源，写回 `.env` |
| `-Part all` | 两者都做（默认） |

- 下载走 4 个镜像（codeload / gh-proxy / ghfast / ghproxy.net）
- 源列表没实质变化时不写盘、不重启，避免打断观看
- 日志：`logs/update.log`

> ⚠️ 短剧内核由第三方独立维护，上游接口一旦调整就会失效，只能等对方更新。这是这条路线的固有风险。

```bash
# 1) 主站

npm install
```

`app/next.config.ts` 里把 `/hg-api/*` 转发到 `http://127.0.0.1:8000`，可用环境变量 `HONGGUO_API` 覆盖。

## 已知限制

1. **没有代码签名**：Windows SmartScreen 会提示未知发布者；macOS 需手动放行。
2. **短剧首播慢**：单集需取流 + 转封装 + 转码，约 10–20 秒；命中缓存后秒开。
3. **短剧依赖第三方内核**：接口或参数一变就失效，要等 hongguo-web 跟进。
4. **播放器未统一到 ArtPlayer**：短剧页用原生 `<video>`（保留画中画/全屏），短剧该有的倍速记忆、快捷键、手势已用原生方式补齐。
5. **只支持 x64（Windows）**，ARM64 Windows 未打包。
